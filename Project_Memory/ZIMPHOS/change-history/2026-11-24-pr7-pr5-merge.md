collections, count checks, additive) and PR #5 (`experimental` → `main`:
phone app rework, driver app, desk shop page, collections — depends on #7)

explicitly overridden by the user for this merge).

## Why this is worth a change-history entry
Merging #5 after #7 required resolving real conflicts — both touched
`docs/contracts/openapi.yaml`, `docs/contracts/README.md`,
`frontend/src/services/api/schema.d.ts`, and `frontend/src/pages/desk/StockPage.tsx`.
The resolution isn't obvious from the diff alone:
- `StockPage.tsx`: #7's fix had added an explicit `fulfilment: 'delivery'`
  to a hand-written booking call inside `StockPage.tsx`. #5 had already
  deleted that whole inline form and replaced it with the new
  `DispatchForm` component (which sets `fulfilment` itself). The merge took
  #5's version wholesale and dropped #7's now-redundant patch.
- `schema.d.ts`: rather than hand-resolve the generated-file conflict,
  regenerated it fresh from the merged `openapi.yaml` via `npm run gen:api`
  — per the project's "change the contract first, regenerate frontend
  types, never hand-write" rule.
- Doing this surfaced a previously-undetected contract/frontend drift:
  TypeScript failed after regeneration because `StockPage.tsx`'s delivery
  booking call didn't set `fulfilment`, which only became a required field
  in the generated types once `DispatchItem`'s `fulfilment` field was
  picked up. Fixed before #7's commit, then superseded again by #5 as
  described above.
