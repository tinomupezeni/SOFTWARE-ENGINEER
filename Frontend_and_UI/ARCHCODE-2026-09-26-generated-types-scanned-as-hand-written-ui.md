# Generated OpenAPI types were scanned as hand-written UI, flagging a verdict field that is only a type

**Date:** 2026-09-26
**Project:** ArchCode (pixel-perfect-replication scaffold)
**Environment:** Development
**Severity:** Medium
**Status:** Resolved

## Summary
`src/lib/api-schema.d.ts` is generated by `openapi-typescript` from `openapi/archcode.yaml`
and carries the header "Do not make direct changes to the file." The file walker in
`verify-semantics.ts` collected it because it matches `/\.tsx?$/`, and the honesty rule for
fabricated verdicts — `/\bpassed:\s*boolean/` — fired on the declaration
`invariants[].passed: boolean`. That field is the *type* of a verdict a future runner will
return, not a claim that a verdict exists. A type declaration was being reported as a
fabricated verdict.

## Symptoms
- `FAIL src/lib/api-schema.d.ts:137  verdict threaded into the UI with no run behind it`
- The rule's stated concern — the UI showing a verdict with no run behind it — is not what the
  file contains; it is an interface for a response that does not exist yet.
- Editing the file to fix the failure is impossible by design: the header forbids it and
  `api:types` regenerates it.

## Environment Details
- **Server/Host:** local dev (`npx tsx scripts/verify-semantics.ts`)
- **Services Affected:** `scripts/verify-semantics.ts` (file collection)
- **Related Components:** `openapi/archcode.yaml`, `src/lib/api-schema.d.ts`
- **Time First Observed:** 2026-09-26, once the honesty reporter stopped crashing

## Investigation Steps

### 1. Initial Diagnosis
The failure pointed at a generated declaration file.

### 2. Root Cause Analysis
```bash
sed -n '130,140p' src/lib/api-schema.d.ts
#   invariants: { name: string; expected: string; observed: string; passed: boolean; }[];
head -4 src/lib/api-schema.d.ts
#   auto-generated by openapi-typescript.  Do not make direct changes to the file.

grep -n 'function walk' -A 5 scripts/verify-semantics.ts
#   else if (/\.tsx?$/.test(entry)) out.push(full);   // .d.ts ends in .ts, so it is collected
```
The exclusion list named exactly one file, `lib/semantics.ts`, by hand. Everything else under
`src/{routes,components/arch,lib}` was scanned, generated or not.

### 3. Key Findings
- `api-schema.d.ts` was regenerated during the session (mtime 16:43) with content that
  included the `passed: boolean` field, so the false positive appeared without any change to
  the check itself.
- The failure was previously invisible: the honesty reporter crashed on its first finding, so
  one bug masked the other.
- The rule and the file are both correct in isolation. The defect is the file set.

## Root Cause
Source-text rules are written for hand-written source, and the collector treated the whole
`src/` tree as hand-written. Generated files are *especially* prone to false positives here
because an OpenAPI schema is, by construction, a declaration of every field the product might
eventually have — including the ones honesty rules exist to prevent from appearing before
they are earned. A generated contract is the most legitimate place for `passed: boolean` to
appear and simultaneously the least relevant.

## Prevention / Rule
**Guardrail:** Detect generated sources by their own banner (`auto-generated`, `DO NOT EDIT`,
"do not make direct changes") or by a `.d.ts` suffix, exclude them from every source-text
check, and **print the excluded paths on every run**; additionally throw if the exclusion
would leave the scan with zero files.

Printing the exclusion is the load-bearing part. Silently skipping files is its own hazard: it
can hide a hand-written file that a generator once touched, and it can turn a scan vacuous
without anyone noticing. The zero-files guard is what stops "everything was classified as
generated" from reading as a clean run.

## Solution

### Immediate Fix
Added an `isGenerated()` check used to exclude generated files from the scan, with the excluded
paths logged on every run and a hard failure if the exclusion empties the file set:

```
ok    generated sources excluded from source checks (1): src/lib/api-schema.d.ts
```

### Long-term Fix
If more generators are adopted, extend the banner list. The detection is banner-based rather
than a hardcoded path list precisely so that adding a generator does not require remembering
to update a list of filenames.
