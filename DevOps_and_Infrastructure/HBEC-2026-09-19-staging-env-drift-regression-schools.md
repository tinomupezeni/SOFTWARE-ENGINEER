# Environment Drift Regression on Staging (Schools Backend 403)

**Date:** 2026-09-19
**Project:** HBEC
**Area:** DevOps and Infrastructure

## Issue Description
A 403 Forbidden error resurfaced when the Admin Frontend attempted to fetch `/api/schools/institutions/`. This was a regression of the previously documented issue (HBEC-2026-09-19-staging-env-drift-401-403-502.md).

## Root Cause
- **Partial Deployment Regression:** While attempting to deploy an update to `admin-frontend`, the command `docker compose up -d admin-frontend` was used. This command recreated `admin-frontend` and its direct dependencies (including `admin-backend`) with the latest environment variables from `.env`.
- However, `schools-backend` was skipped during this targeted deployment.
- As a result, `admin-backend` picked up the new `SCHOOLS_ADMIN_SECRET` ("ef036a20f..."), while `schools-backend` was still running with the old secret ("hbec-schools-admin-dev-key").
- The HMAC signature generated by `admin-backend` failed validation in `schools-backend`, resulting in the 403 Forbidden error.

## Resolution
- Ran a full `docker compose -f docker-compose.staging.yml up -d` without specifying services to ensure ALL containers (including `schools-backend` and `student-backend`) were recreated and synchronized with the latest `.env` configuration.
- To prevent future regressions, any deployment script or manual update should run `docker compose up -d` globally rather than targeting individual services when `.env` configurations are shared across microservices.
